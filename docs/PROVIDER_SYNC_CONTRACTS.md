# Provider synchronization contracts (0.0.1)

`RemoteMessage` carries a provider ID, an aware reception timestamp, its provenance, and a bounded raw RFC 822 byte stream. The Date header is stored as a separate sender timestamp when valid; it never replaces a missing provider reception time. `service.py` checks reception ranges with inclusive UTC start and exclusive UTC end and preserves the provider timestamp and provenance for filtered candidates.

| Provider | Message identity within one source | Reception time | Automatic cursor | Manual preselection |
| --- | --- | --- | --- | --- |
| Gmail API | Gmail message ID across labels | `internalDate` epoch milliseconds | History ID; a rejected/expired history ID causes a full ID reconciliation | `messages.list` `q` with conservative epoch-second `after`/`before` |
| Microsoft Graph | Immutable ID across folders within one mailbox | `receivedDateTime` | Folder delta link; expired links cause full ID reconciliation | Folder messages listing with reception filter |
| Generic IMAP | Folder, UIDVALIDITY, UID | `INTERNALDATE` | Per-folder UID within UIDVALIDITY | `SEARCH SINCE/BEFORE` with overlapping calendar days |

The Graph `Prefer: IdType="ImmutableId"` header is sent on folder listings, message metadata, MIME downloads and delta requests. Folder membership is separate from message identity. Before reserving a Graph delta candidate, the adapter verifies that it still belongs to a selected folder. A pending intake is released if a targeted recheck finds that the message was moved outside every selected folder. Gmail labels are memberships of the same ID. Gmail keeps one mailbox History cursor and records a baseline for each selected label. A newly selected label gets a full baseline before the shared History cursor is replayed; a failed label baseline stops that run and leaves the shared cursor unchanged. Removing any selected folder or label clears its scope marker, so re-adding it starts a new baseline. Re-enabling a disabled source also creates fresh baselines. A newly selected Graph or IMAP folder establishes its own baseline without disturbing other folder cursors or accepted plans.

Every provider preselection is followed by an exact UTC check. IMAP search dates ignore clock time and timezone. Gmail's date strings have PST semantics, so the adapter uses epoch seconds with one-second slack. Graph filters use `receivedDateTime` and the adapter reads the actual message metadata before archiving. A provider that omits or corrupts the required timestamp produces a visible intake error.

Raw messages are capped at 256 MiB. IMAP reads `RFC822.SIZE` before starting bounded `BODY.PEEK` partial requests. Graph MIME responses are read in bounded chunks. Gmail's JSON `raw` field is extracted and base64url-decoded incrementally, so the encoded response is never assembled as one large value. The spool checks the per-message limit, total work-folder use, and free-space reserve during the transfer. A declared or observed excess stops the stream before plan acceptance.

Automatic discovery is driven by provider IDs and cursors. It never uses `received_at > last_run` as a cursor. A newly imported message with old reception time can therefore still be processed. A manual range scan keeps its own run state and never advances the automatic cursor. An interrupted manual scan restarts enumeration with its saved source, folders, UTC range, confirmed timezone, and rule snapshot; completed output receipts prevent duplicate files. If an unresolved intake is no longer returned, the run remains failed until it can be resumed or is explicitly cancelled. Provider result sets are live, not transaction snapshots.

If a provider message disappears after reservation while its body is streaming, the current run reports a concrete intake failure and retains the known reception timestamp and provenance. The reservation remains retryable until a later provider reconciliation confirms that the ID has left the source scope; that reconciliation releases the active reservation but keeps the earlier error in processing history.

A change in IMAP UIDVALIDITY pauses the affected folder. The user can choose a new baseline or run an explicit range; old UID receipts are not inferred to identify new UIDs. The reset cancels unfinished intakes in that folder, because no local raw copy was accepted, and preserves accepted plans. Different providers, aliases, and IMAP folders are not universally deduplicated.

References: [Gmail search and epoch dates](https://developers.google.com/workspace/gmail/api/guides/filtering), [Gmail message `internalDate`](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages), [Graph message](https://learn.microsoft.com/en-us/graph/api/resources/message?view=graph-rest-1.0), [Graph immutable ID](https://learn.microsoft.com/en-us/graph/outlook-immutable-id), and [IMAP RFC 9051](https://www.rfc-editor.org/rfc/rfc9051.html).
