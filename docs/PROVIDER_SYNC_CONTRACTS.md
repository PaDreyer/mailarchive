# Provider synchronization contracts (0.0.1)

`RemoteMessage` carries a provider ID, an aware reception timestamp, its provenance, and a bounded raw RFC 822 byte stream. The Date header is stored as a separate sender timestamp when valid; it never replaces a missing provider reception time. `service.py` checks reception ranges with inclusive UTC start and exclusive UTC end and preserves the provider timestamp and provenance for filtered candidates.

| Provider | Message identity within one source | Reception time | Automatic cursor | Manual preselection |
| --- | --- | --- | --- | --- |
| Gmail API | Gmail message ID across labels | `internalDate` epoch milliseconds | History ID; a rejected/expired history ID causes a full ID reconciliation | `messages.list` `q` with conservative epoch-second `after`/`before` |
| Microsoft Graph | Immutable ID across folders within one mailbox | `receivedDateTime` | Folder delta link; expired links cause full ID reconciliation | Folder messages listing with reception filter |
| Generic IMAP | Folder, UIDVALIDITY, UID | `INTERNALDATE` | Per-folder UID within UIDVALIDITY | `SEARCH SINCE/BEFORE` with overlapping calendar days |

The Graph `Prefer: IdType="ImmutableId"` header is sent on folder listings, message metadata, MIME downloads and delta requests. Folder membership is separate from message identity. Before reserving a Graph delta candidate, the adapter verifies that it still belongs to a selected folder. A pending intake is released if a targeted recheck finds that the message was moved outside every selected folder. Gmail labels are memberships of the same ID. Gmail keeps one mailbox History cursor and records a baseline for each selected label. A newly selected label gets a full baseline before the shared History cursor is replayed; a failed label baseline stops that run and leaves the shared cursor unchanged. Removing any selected folder or label clears its scope marker, so re-adding it starts a new baseline. Re-enabling a disabled source also creates fresh baselines. A newly selected Graph or IMAP folder establishes its own baseline without disturbing other folder cursors or accepted plans.

Graph continuation and delta URLs are reused unchanged, including their opaque query tokens. Link validation accepts both `/mailFolders/{id}` and the documented OData `/mailfolders('{id}')` form. If Graph replaces a configured folder alias such as `INBOX` with its ID, the adapter resolves the configured folder and checks that ID before accepting the link. Links must retain the HTTPS Graph origin, API version, selected mailbox, and message collection; folder IDs remain case-sensitive. See [Microsoft's message delta examples](https://learn.microsoft.com/en-us/graph/delta-query-messages).

Every provider preselection is followed by an exact UTC check. IMAP search dates ignore clock time and timezone. Gmail's date strings have PST semantics, so the adapter uses epoch seconds with one-second slack. Graph filters use `receivedDateTime` and the adapter reads the actual message metadata before archiving. A provider that omits or corrupts the required timestamp produces a visible intake error.

Raw messages are capped at 256 MiB. IMAP reads `RFC822.SIZE` before starting bounded `BODY.PEEK` partial requests. Graph MIME responses are read in bounded chunks. Gmail's JSON `raw` field is extracted and base64url-decoded incrementally, so the encoded response is never assembled as one large value. The spool checks the per-message limit, total work-folder use, and free-space reserve during the transfer. A declared or observed excess stops the stream before plan acceptance.

Automatic discovery is driven by provider IDs and cursors. It never uses `received_at > last_run` as a cursor. A newly imported message with old reception time can therefore still be processed. An empty successful check updates source health without creating an Archive activity job. A manual range scan keeps its own run state and never advances the automatic cursor. **Apply to past mail** freezes the enabled rule, selected mailboxes and folders, UTC range, and confirmed timezone for the whole operation. Retrying a failed or interrupted scan uses that snapshot and retains earlier scan attempts; accepted outputs retry from the local raw copy. A manual operation stays in Current jobs while accepted outputs are unfinished. **Stop selected job** stops the entire selection and prevents later output retries; a publication already in flight may finish and record its receipt. If an unresolved intake is no longer returned, the affected scan reports the failure in Archive activity. Provider result sets are live, not transaction snapshots.

Automatic checks, including **Check mail now**, select only enabled accounts with enabled mailboxes and at least one current enabled rule scoped to that account (or all accounts). Content conditions do not participate in this preflight. Accounts without such a rule are skipped before folder enumeration, scan creation, or message retrieval; their baselines, cursors, message markers, and last-check state stay unchanged. Manual checks with no eligible account return an informational notice without entering the execution queue. Queued checks revalidate the selection before execution, then retain the existing frozen-settings semantics for the running check. Automatic polling skips ineligible accounts without recurring notices or log entries.

Unfinished automatic intakes also require a current applicable enabled rule for their saved source account before another provider request. Both execution and the work-due query honor this pause, including forced automatic retries. Accepted plans with local raw copies can still finish outputs using their saved rules. Rule changes do not reset synchronization state or earlier baseline/unmatched markers, and require no database migration. After a rule pause, an established cursor continues from its preserved position; an account without a baseline performs its first actual check according to **Archive messages already present on the first check**. Earlier baseline or unmatched mail remains available through **Apply to past mail**.

A receipt records a prior successful output. Reapplying a rule can reuse that receipt without writing a duplicate file; Archive activity identifies the result as **Previously archived** and shows the original completion time. Reapplication does not audit or recreate an output deleted after its earlier successful write. Opening an output checks that its recorded file is still present.

If a provider message disappears after reservation while its body is streaming, the current run reports a concrete intake failure and retains the known reception timestamp and provenance. The reservation remains retryable until a later provider reconciliation confirms that the ID has left the source scope; that reconciliation releases the active reservation but keeps the earlier error in Archive activity History.

A change in IMAP UIDVALIDITY pauses the affected folder. The user can choose a new baseline or run an explicit range; old UID receipts are not inferred to identify new UIDs. The reset cancels unfinished intakes in that folder, because no local raw copy was accepted, and preserves accepted plans. Different providers, aliases, and IMAP folders are not universally deduplicated.
