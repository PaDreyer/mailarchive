# MailArchive 0.0.1

MailArchive 0.0.1 starts a new local product format. It is a fresh installation;
earlier prototype settings and processing databases are not imported.

- Rules use the first active match and can write mail and attachments to several
  independent, full paths.
- Automatic monitoring first records the existing source scope as a baseline.
  Explicit range runs can archive reachable existing mail using provider reception
  dates and current rules.
- Accepted work keeps a local raw mail copy until all requested outputs complete or
  the plan is explicitly aborted. Successful individual outputs are remembered, so
  a later range run can add a new destination without copying an old one again.
- Open work shows intake, plan, destination, and output errors. Plans can be paused
  without discarding their local copy; interrupted range runs can be resumed or
  cancelled without leaving hidden reservations.
- Processing history retains completed and aborted plans as well as nonaccepted
  intake attempts, with source, reception time, frozen rule, destination status,
  output paths, and errors. Older entries are available through stable pagination.
- Provider message bodies are streamed into the work folder with a 256 MiB
  per-message limit, a 2 GiB total capacity, unambiguous exact declared-length
  checks, and continuous disk-reserve checks. The work directory and its accounting
  do not follow symlinks.
- IMAP body chunks are bound to the requested UID and offset, while OAuth HTTP
  redirects are restricted to the same HTTPS origin.
- Discovery pauses at 256 unresolved message intakes until existing errors are
  retried or cancelled, preventing an unbounded persistent discovery queue.
- Run cancellation and intake reservation are serialized so a cancelled run cannot
  acquire hidden work. Failed raw-file publication does not leave an orphan, and a
  transient cleanup failure after completion or abort is retried without reversing
  the durable result.
- The profile keeps configuration, source identity, runs, work state, receipts, and
  activity in one local SQLite database. Reverse active-work references are checked
  when the profile opens and during every live transition; credentials remain in
  the platform store.

The download packages are named for version 0.0.1. This note is intentionally
independent of earlier Git tags.
