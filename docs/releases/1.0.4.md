# MailArchive 1.0.4

MailArchive 1.0.4 fixes parsing failures caused by malformed MIME headers, including
empty encoded attachment filenames and broken Content-Type parameters. It preserves
email bodies and attachment bytes, recovers filenames where possible, and uses
`Attachment` when no usable filename is available.

Message-IDs wrapped in extra square brackets, such as `<[id@example.com]>`, are now
parsed as `<id@example.com>` when the inner ID is valid. Affected messages can be
matched against rules and archived normally. The original email bytes and attachment
content remain unchanged, and subsequent checks do not archive processed messages again.

When an individual message still fails, the activity log now includes the source
filename, line number and function alongside the email ID and error type. Failed
messages remain eligible for retry on later checks.

Existing account and rule settings remain compatible. The database and settings
schemas are unchanged, and previously archived mail remains intact. Update using the
new Windows installer or Linux AppImage as described in the [README](../../README.md#updates).
